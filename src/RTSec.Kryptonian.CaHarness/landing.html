Background

The Problem: Unprotected DICOM Streams

Legacy DIMSE has no device authentication — any host on the network can impersonate a scanner, PACS, or treatment system. Your gateway fixes this by issuing and enforcing certificates through EST, binding device identity to every connection before a single DICOM file moves.

Challenge

The Three Scoring Flows

🔒
Flow 1 — DIMSE mTLS C-STORE
×4 backends  ·  4 pts max

Enroll a device through your gateway using the protocol required by each backend: EST for selfsigned, SCEP for adcs, EJBCA REST for ejbca, and ACME for acme. Present the issued certificate as mTLS client credential to the DIMSE TLS proxy on port 4243. C-STORE a DICOM file. Scored independently per backend.

selfsigned → EST /est/selfsigned/simpleenroll adcs      → SCEP /scep/adcs?operation=PKIOperation ejbca     → REST /ejbca/ejbca-rest-api/v1/certificate/pkcs10enroll acme      → ACME /acme/directory
⇄
Flow 2 — C-MOVE → DICOMWeb
1 point

Trigger a C-MOVE from Orthanc (port 4242, plain DIMSE) to your SCP. Receive the DICOM file. Submit it to the harness via STOW-RS with your gateway-enrolled certificate in the request header.

POST /teams/{token}/dicom/backends/{backend}/stow
🌐
Flow 3 — DICOMWeb → DIMSE
1 point

Retrieve a DICOM study via WADO-RS from Orthanc's DICOMweb API. Convert and C-STORE the file back to Orthanc on plain port 4242. Claim the score by posting the SOP instance UID to the harness.

GET http://...8042/dicom-web/studies/{uid}/...

Backends

Four CA Backends — Four Score Columns

🔑
selfsigned

Generic self-signed CA. No template required. Best for fast iteration and initial testing.

🏢
adcs

Microsoft AD Certificate Services. Use template DicomDeviceAuthentication or DicomBridgeMtls.

🛡️
ejbca

EJBCA Enterprise PKI. Use certificate profile MedicalDeviceTLS or DicomWebBridgeMTLS.

🌐
acme

ACME protocol via step-ca. Point your gateway DirectoryUrl at the harness ACME endpoint.
