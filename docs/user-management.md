# User Management

This guide covers how to create accounts, manage users, control access, and generate API keys in the Kryptonian MEDIATE Gateway.

---

## Roles

Every account in Kryptonian has one of three roles.

| Role | What they can do |
|---|---|
| **Standard** | View dashboards, devices, certificates, EST profiles, CA backends, and the event log. Read-only access — cannot change any settings or register devices. |
| **DeviceAdmin** | Everything Standard can do, plus: register/approve/remove devices, and generate API keys for scripted device management. |
| **SystemAdmin** | Full access — all of the above plus: create and manage users, change CA backends, configure EST profiles, modify gateway and notification settings. |

---

## First-Time Setup

When the gateway starts for the first time with an empty database, the browser shows a **Create Administrator Account** wizard instead of the login screen.

Fill in a username, email address, password (minimum 8 characters), and confirm the password. Click **Create Admin Account**. This creates the first SystemAdmin and immediately signs you in.

> If the gateway is deployed with `KRYPTONIAN__AUTH__INITIAL_ADMIN_USERNAME` and `KRYPTONIAN__AUTH__INITIAL_ADMIN_PASSWORD` environment variables set, the first admin is created automatically and the UI skips the wizard and shows the login screen.

## Signing In and Out

Navigate to the gateway URL. If accounts exist, the **Sign In** screen appears. Enter your username and password and click **Sign In**. Your session lasts 8 hours; after that you are returned to the login screen.

To sign out, click **Sign out** at the bottom of the left sidebar.

---

## Managing Users *(SystemAdmin only)*

Select **Users** from the left sidebar. The table lists every account with its username, email, role, active status, and the date it was created.

### Add a user

1. Click **Add User**.
2. Enter a username, email address, role, and initial password (minimum 8 characters).
3. Click **Create User**. The new account appears in the table immediately.

Share the username and initial password with the new user out of band and ask them to treat the password as temporary.

### Change a user's role or reset their password

1. Click the edit icon (pencil/person icon) on the user's row.
2. Select a new role from the dropdown, or enter a new password (leave the password field blank to keep the current one).
3. Click **Save Changes**.

### Deactivate or reactivate a user

Click **Deactivate** or **Activate** on the user's row. Deactivated users cannot sign in and their API keys stop working, but the account and all its history are preserved.

### Delete a user

Click the red **Delete** (trash) button on the user's row and confirm. Deletion is permanent. You cannot delete your own account, and the system blocks deleting the last active SystemAdmin to prevent lockout.

## API Keys

API keys let scripts, CI pipelines, and medical devices authenticate to the REST API using the `X-API-Key` header — no browser session required. Keys are available to DeviceAdmin and SystemAdmin accounts.

Select **API Keys** from the left sidebar.

- **SystemAdmin** sees all keys across every user, including the key owner's username.
- **DeviceAdmin** sees only their own keys.

### Generate a key

1. Click **Generate Key**.
2. Enter a descriptive name (for example: `CT scanner – Bay 3` or `CI pipeline`).
3. Optionally set an expiry date. Leave blank for a key that never expires.
4. Click **Generate**.

The raw key is shown **once** in a copy-to-clipboard dialog. Copy it immediately — it cannot be recovered after you close the dialog. The table will show only the first 8 characters (prefix) for identification.

Use the key in REST API requests:

```
X-API-Key: kry_<rest of key>
```

Keys carry the role of their owner at the time of generation. A key generated by a DeviceAdmin always acts as DeviceAdmin, even if the owner's role changes later.

### Revoke a key

Click **Revoke** on the key's row and confirm. Revocation is immediate and permanent — the key stops working instantly and cannot be reinstated. Generate a new key if access is still needed.

---

## Password Requirements

- Minimum 8 characters.
- No maximum length.
- No complexity rules enforced by the gateway — choose a strong, unique password.

---

## Frequently Asked Questions

**I forgot my password.** A SystemAdmin can reset it via the Edit User dialog (Users page). If no SystemAdmin is available, contact the person who deployed the gateway — they can set `KRYPTONIAN__AUTH__INITIAL_ADMIN_USERNAME` and `KRYPTONIAN__AUTH__INITIAL_ADMIN_PASSWORD` env vars to re-seed an admin on restart (only works on a fresh database; contact support for recovery on an existing installation).

**My session expired.** JWT sessions last 8 hours. Sign in again — your settings and data are unchanged.

**An API key stopped working.** Check the Keys table for the key's status. It may have been revoked, reached its expiry date, or the owning account may have been deactivated. Generate a new key if needed.

**Can I use the old `KRYPTONIAN__ADMINAPI__APIKEYS` env var?** Yes. Static keys set in that environment variable continue to work as SystemAdmin for backward compatibility with existing automation. Migrate to user-generated API keys when convenient.
